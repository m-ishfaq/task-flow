How it's built

Built to make mistakes impossible, not just unlikely.

Tenant-scoped by construction One policy gate for every permission Raw SQL & crypto banned by lint Hash-chained audit log

This was built mostly solo, with AI doing most of the actual typing — which meant I couldn't rely on catching every mistake the way a full team's code review would. So instead of trusting vigilance, the architecture is designed so entire classes of security bugs can't be expressed at all.

Every database query runs through one tenant-scoped client — skip it, and the query returns zero rows, never another company's data. Every permission check runs through a single policy module; comparing roles inline anywhere else is a lint error. Raw SQL, cryptographic primitives, and non-cryptographic randomness are banned outside a handful of files, audited by hand, one primitive per file. And every action that changes something writes a tamper-evident, hash-chained entry to an audit log — a write can't be quietly altered after the fact.

It isn't flawless. Real bugs have been found and fixed this way — including a caching issue that briefly showed one account's data after switching users. That's exactly why this is live at an early, rough stage instead of sitting private until it feels finished.
